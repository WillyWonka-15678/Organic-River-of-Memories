# 伸手拾忆与挥手送别

2026-10-22。保留主河流、Body Wake、配色和字形风格，只修改留言控制与字形聚散。

## 操作

1. 启动时默认五条随机留言分散在屏内不同流束上，立即开始漂流，后续留言持续从左侧补充。进入身体 Mask 后缓慢漂移，离开身体后恢复。
2. 将单手伸至肩膀附近高度，向侧面伸出并停留约 0.7 秒。最近的留言会柔和跟随手腕；附近没有留言时，以约 1.6 秒金色粒子汇聚形成新留言。
   锁定后约 3 秒内平滑放大至原文字三倍，笔画同步增粗、渐亮，并浮现柔和暖金光晕。送别保持放大后的字形再消散；识别丢失解除锁定后约 2.5 秒恢复原尺寸与亮度。
3. 持有留言后，做有明显横向幅度的往返挥手。一次单向移手不会直接送别。留言约 3.5 秒内保持短暂字形后舒展、淡出归流。
4. 放下手再伸出可进行下一次拾忆。第一版全局同时允许一条被捕获或释放的留言，双手以先完成停留者为准。

普通挥手不会打碎其他留言。短暂遮挡保持最后位置；有效手部输入丢失超过 1.2 秒后取消持有并完整恢复漂流。由于 Pose 本身有置信度衰减，实际从遮挡开始计时会略长。

## 模块与优先级

- `MemoryInteraction.ts`：CPU 上最多八条逻辑留言，独立状态、生成、手势历史、冷却和丢失恢复。
- `MemoryLayer.ts`：复用 PoseTrack 映射后的关键点与实际 Mask alpha；三个水平采样点衡量覆盖，进入阈值 0.60、离开 0.35。统一控制整句速度；字形缓存避免每帧重新采样。GPU 顶点 Shader 负责召唤聚合与释放散开。
- `main.ts`、`config.ts`：记忆参数、实际时间步和开发测试入口。隐藏星座显示仍可使用文字手势。

状态关系：`FLOWING ↔ BODY_SLOWED → CAPTURED → RELEASING → 回收`。FLOWING 也可直接捕获。持续丢失时 CAPTURED 回到 FLOWING，随后重新判断 Mask。捕获与释放均跳过普通流场/身体减速规则。原有周期自动解体不再运行。

手腕位置指数平滑；速度按时间计算；距离、挥手幅度和速度按肩宽及画幅归一化。往返轨迹窗口 1.5 秒，冷却 1.5 秒。大于 0.25 秒的后台停顿不作一次完整动画步，避免恢复页面时瞬移。

左右伸手使用相同判断。靠近画面边缘或侧身时，只要同侧肩、肘、腕可靠可见，另一侧肩膀遮挡不会让整条手臂失效；双肩不完整时改用可见手臂长度估计动作尺度，不使用遮挡肩膀的旧坐标。缺失关节仍按各自置信度淡出，不补造人体连接。

默认普通留言上限五条、生成间隔八秒、速度 0.023 屏宽/秒。捕获不停止普通生成，总活动对象上限八条。参数入口「参数 → 记忆交互」可调数量、频率、漂流速度、身体减速、捕获范围、停留时间、释放时长。

释放粒子沿现有河流中心线的局部切线舒展，受控偏移并淡出；当前为 GPU 字形过渡，不把每颗字粒子移交主河流粒子池。

## 验证

`npm.cmd test`：逻辑测试覆盖减速迟滞、捕获、召唤、双手竞争、遮挡、挥手与单向移手区别、空手挥动、生成上限及 30/120 Hz 时间一致性。

`npm.cmd run test:browser -- tests/browser/memory.spec.ts`：1920×1080 Edge / 软件 WebGL，注入姿态和人体轮廓，验证完整状态与实际 Shader 渲染，截图在 `test-results/memory-*.png`。

需要真人摄像头验证：不同距离下伸手停留及挥手阈值、手腕短暂遮挡、放手后再次拾忆、两只手竞争、镜像对齐，以及大屏上汇聚/释放的观感与文字可读性。软件 WebGL 与合成姿态不代表目标显卡性能或真人识别准确率。本轮没有执行持续运行压力测试。


第二行姓名、年份和专业使用 12px 中等字重、逐像素采样的细粒文字，并减弱锁定光晕以保护笔画；与主寄语共用捕获、放大与释放状态。
